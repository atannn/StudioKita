# Panduan Live Coding StudioKita

Dokumen ini berisi kemungkinan soal live coding dari penguji, jawaban lisan yang aman, lokasi file yang perlu diubah, bagian yang diganti, dan contoh kode penggantinya.

Catatan penting:

- Jangan menerapkan semua perubahan sekaligus ke aplikasi.
- Terapkan hanya perubahan yang diminta penguji.
- Jika penguji meminta alasan, tekankan bahwa perubahan dilakukan pada lapisan validasi controller/service agar data tidak rusak sebelum masuk database.
- Setelah perubahan, sebutkan bahwa pengujian minimal dilakukan lewat skenario sukses, skenario gagal, dan pengecekan database.

## 1. Mencegah Booking Pada Jadwal Yang Sudah Lewat

### Pertanyaan Penguji

"Bagaimana kalau customer mencoba booking jadwal yang waktunya sudah lewat?"

### Jawaban Lisan

Pada sistem booking, validasi tidak cukup hanya mengecek status jadwal available. Sistem juga harus memastikan waktu mulai jadwal masih berada di masa depan. Validasi ini diletakkan di `StudioBookingController` karena proses booking dilakukan dari controller tersebut sebelum data booking dan payment dibuat.

### File

`app/Http/Controllers/StudioBookingController.php`

### Letak Perubahan

Di method `store()`, setelah `$jadwal->refresh();` dan sebelum validasi status jadwal.

### Tambahkan Kode

```php
$slotStart = \Carbon\Carbon::parse($jadwal->tanggal.' '.$jadwal->waktu_mulai);
if ($slotStart->isPast()) {
    return back()
        ->withErrors(['jadwal_id' => 'Jadwal yang dipilih sudah lewat. Silakan pilih jadwal lain.'])
        ->withInput();
}
```

### Contoh Posisi

```php
$this->availability->recomputeRoomDate(
    (int) $tenant->idTenant,
    (int) $validated['rooms_idrooms'],
    $date
);
$jadwal->refresh();

$slotStart = \Carbon\Carbon::parse($jadwal->tanggal.' '.$jadwal->waktu_mulai);
if ($slotStart->isPast()) {
    return back()
        ->withErrors(['jadwal_id' => 'Jadwal yang dipilih sudah lewat. Silakan pilih jadwal lain.'])
        ->withInput();
}

if ($jadwal->status !== 'available') {
    return back()
        ->withErrors(['jadwal_id' => 'Jadwal yang dipilih baru saja dipesan. Silakan pilih slot lain.'])
        ->withInput();
}
```

### Testing

- Pilih jadwal yang waktunya sudah lewat.
- Sistem harus menolak booking.
- Pilih jadwal yang masih aktif.
- Sistem harus tetap bisa membuat booking.

### File

```php
    try {
        $snap = $this->midtrans->createSnapTransaction($tenant, $booking, $payment, $user);
        $payment->update([
            'midtrans_order_id' => $snap['order_id'],
            'snap_token' => $snap['token'],
            'snap_redirect_url' => $snap['redirect_url'],
            'status' => 'pending',
            'raw_status' => 'snap_created',

            (int) $tenant->idTenant,
            (int) $validated['rooms_idrooms'],
            $date

    }

    $payment->update([
        'status' => 'pending',
        'raw_status' => 'midtrans_not_configured',
    ]);

```

## 7. Validasi `gross_amount` Pada Callback Midtrans

### Jawaban Lisan

Selain memvalidasi signature key, sistem juga perlu memastikan `gross_amount` dari Midtrans sama dengan nominal payment di database. Jika tidak sama, status pembayaran tidak boleh diubah menjadi success.

### File

`app/Http/Controllers/PaymentController.php`

### Letak Perubahan

Di method `midtransWebhook()`, setelah payment ditemukan dan sebelum payment diupdate.

### Tambahkan Variabel Sebelum `runForTenant`

```php
$amountMismatch = false;
```

### Ubah Pemanggilan Closure Agar Membawa Variabel

```php
$this->tenantDbManager->runForTenant($tenant, function () use ($payload, $ids, $tenant, &$amountMismatch) {
```

### Tambahkan Kode Setelah `$payment` Ditemukan

```php
$grossAmount = round((float) ($payload['gross_amount'] ?? 0), 2);
$expectedAmount = round((float) $payment->amount, 2);

if (abs($grossAmount - $expectedAmount) > 0.01) {
    $amountMismatch = true;

    $payment->update([

        'webhook_payload' => $payload,
    ]);
```

```php
    return response()->json([
        'message' => 'Nominal callback tidak sesuai dengan payment.',
    ], 422);
}
```

## 9. Membatalkan Booking Pending Yang Jadwalnya Sudah Lewat

### Pertanyaan Penguji

"Kalau booking pending tidak dibayar sampai jadwal lewat, bagaimana membersihkannya?"

### Jawaban Lisan

Booking pending yang sudah melewati waktu mulai jadwal sebaiknya diubah menjadi cancelled agar tidak menggantung. Perubahan bisa dilakukan dengan scheduler, command, atau validasi sebelum halaman owner ditampilkan.

### Solusi Cepat Untuk Live Coding

Tambahkan helper di `app/Http/Controllers/Owner/BookingController.php`.

### Tambahkan Method Private

```php
private function cancelExpiredPendingBookings(int $tenantId): void
{
    $expiredBookings = Booking::query()
        ->with('jadwal')
        ->where('tenants_idTenant', $tenantId)
        ->where('status', 'pending')
        ->whereHas('jadwal', function ($query) {
            $query->whereRaw("datetime(tanggal || ' ' || waktu_mulai) < datetime('now')");
        })
        ->get();

    foreach ($expiredBookings as $booking) {
        $booking->payments()
            ->where('status', 'pending')
            ->update([
                'status' => 'cancelled',
                'raw_status' => 'expired_by_system',
                'failed_at' => now(),
            ]);

        $booking->update(['status' => 'cancelled']);

        if ($booking->jadwal) {
            app(\App\Support\ScheduleAvailabilityService::class)->recomputeRoomDate(
                (int) $tenantId,
                (int) $booking->rooms_idrooms,
                (string) $booking->jadwal->tanggal
            );
        }
    }
}
```

### Panggil Di Awal Method `index()`

```php
$this->cancelExpiredPendingBookings($tenantId);
```

### Catatan

Jika tenant database memakai MySQL, ganti query waktu menjadi:

```php
$query->whereRaw("TIMESTAMP(tanggal, waktu_mulai) < NOW()");
```

### Testing

- Buat booking pending pada jadwal yang sudah lewat.
- Buka halaman booking owner.
- Booking harus berubah menjadi cancelled.

### Jawaban

```sql
SELECT
    b.idbooking,
    b.total_harga,
    COALESCE(SUM(p.amount), 0) AS total_paid
FROM bookings b
LEFT JOIN payments p
    ON p.booking_id = b.idbooking
    AND p.status = 'success'
GROUP BY b.idbooking, b.total_harga
ORDER BY b.idbooking DESC;
```
